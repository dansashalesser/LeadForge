1. **Tool-namespace drift in the command's own frontmatter.** `macro-eval-sweep.md` declares
   `allowed-tools: … mcp__raindrop__query_traces, mcp__raindrop__get_run_outline,
   mcp__raindrop__get_current_run, mcp__raindrop__search_run, mcp__raindrop__get_span_payload,
   mcp__raindrop__annotate`, and its Step 0 code block names `mcp__raindrop__query_traces`.
   The server actually registered in this environment is `workshop`, exposing
   `mcp__workshop__query_traces`, `mcp__workshop__get_run_outline`, etc. The `mcp__raindrop__*`
   names resolve to nothing. This run proceeded against the `mcp__workshop__*` equivalents.
   Worth deciding whether the command should be updated to the `workshop` prefix or list both —
   as written, a stricter harness that enforced `allowed-tools` literally would make this sweep
   report "unreachable" on every run while the server was in fact healthy.

   produce signal, instrumentation (or `import_cloud_trace` from a cloud project) likely needs
   to be set up first — otherwise the next several sweeps will land on this same EMPTY path.
