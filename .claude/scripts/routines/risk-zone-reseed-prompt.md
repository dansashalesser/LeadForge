## Step 0: Preflight

- If this is not a git repository, write nothing and exit 0.

## Step 1: Gather signals per file

Scope: every file changed in the last 90 days (`git log --since="90 days ago"
--name-only --pretty=format:`), deduplicated, excluding binaries/lockfiles/generated
output.

For each file, compute:

1. **Churn** — commit count touching the file in the last 90 days
   (`git log --since="90 days ago" --oneline -- <file> | wc -l`).
2. **Test coverage proxy** — does a matching test file exist? (`<name>.test.*`,
   `test_<name>.*`, or a `tests/` entry referencing the file's exported symbols).
3. **Blast radius** — if the `gitnexus` CLI is available (`command -v gitnexus`),
   run `gitnexus impact --target <top-level symbol in file> --direction upstream`
   for the file's most-referenced exported symbol and note the risk level it
   returns (LOW/MEDIUM/HIGH/CRITICAL). Skip this signal gracefully if gitnexus
   isn't installed or the file has no clear top-level symbol — never fail the
   whole reseed over one missing tool.

## Step 2: Score each file

Assign a zone:

- **red** — HIGH/CRITICAL gitnexus impact, OR (high churn AND no matching test file)
- **yellow** — MEDIUM gitnexus impact, OR (moderate churn with a test file present)
- **green** — everything else (low churn, low impact, or well-tested)

When gitnexus impact wasn't available, score from churn + test-presence alone
and note `(impact: not scored)` next to the file so a human knows the signal
was skipped, not deliberately rated green.

## Step 3: Merge with the existing map — do not overwrite human overrides

Read the current `.claude/steering/risk-zones.md` if it exists. Any file marked
with a trailing `<!-- pinned -->` comment keeps its existing zone regardless of
what Step 2 computed — this is how a human overrides the auto-score. Every
other row gets replaced with the freshly computed zone.
